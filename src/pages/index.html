What it makes

The same ui kit and the same calls, whether you want a thing floating over a game or a normal app.

Overlays

A window with no background that sits on top of everything. Clicks go straight through wherever you drew nothing, so the game under it never notices. HUDs, crosshairs, stream overlays, key displays, sticky notes. The same code works on X11, Wayland, Windows and macOS.

Overlay mode · apps to download

Normal app windows

A resizable window with menus, modals, tables, trees, plots, drag and drop and a text editor, drawn by the same kit. No GTK or Qt, no webview. It can run in a browser tab too, the demos below are goome apps built to WebAssembly.

Window mode · App mode and menus

Mod menus and engine ui

goome can live inside a game the way Dear ImGui does. Renderer backends for DX9, DX11, DX12, OpenGL, Vulkan and Metal, packages for Unity, Minecraft, Godot and plain native DLL mods. Offscreen mode hands your engine the pixels if you would rather draw them yourself.

Is it the right one for you

Probably not always, and the compare page says so. goome is a few weeks old, GPL-3.0, has no docking and hardly anyone has written libraries for it yet. Dear ImGui has years on it and Qt has a designer and tested screen readers. Electron has npm.

What goome is built for is the see-through overlay with per region click-through, and getting overlays, normal windows and offscreen drawing out of one file without linking anything.

Theme galleries are coming

goome themes are plain json files, so people can make them and swap them. A place to browse and share them is on the way. Until then the docs show how to make one and the builder has a theme tab.
